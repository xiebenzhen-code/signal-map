# 冻结版线上试用与发布准备

日期：2026-10-04。目标：把当前个人信息过滤开发验证版发布给少量真实用户，验证任务价值。当前尚未完成线上发布。

## 1. 已确认的发布现状

- 现有目标域名：`https://signal.benzhenlab.com`。本次浏览器能打开首页；普通命令行与 Web 读取未成功，不能凭这些失败认定域名整体宕机。
- 线上页面可见不等于当前冻结工作区已部署；尚无线上发行编号与本地内容一致的证据。
- 本地 HEAD：`110d904`，冻结修补仍含未提交文件，必须发布当前工作区需要的内容，不能只推旧 HEAD。
- `edgeone.json` 和 EdgeOne Drop 脚本保留静态发布流程。`prepare-edgeone-drop.mjs` 会输出首页和静态资源；不会提供所有动态页面或 Node API。`/* → /index.html` 的兜底也不能替代 `/api/*` 后端路由。
- 现有 `edgeone.json` 的 Node 22.11.0 低于 package.json 的 >=22.13 要求。若使用此构建入口，应选满足要求的版本；本轮未擅自改变部署配置。
- `/api/signals`、`/api/control/*`、`/api/sources/check` 等需要真实后端；认证路由和页面也需选定适合的运行方式。仅上传静态页面会漏掉这些能力。
- 尚缺部署平台/项目访问、Node 后端承载位置以及上一线上版本的回滚入口。用户无需在聊天发送密码/密钥，应通过控制台或部署平台安全配置。

## 2. 最小发布顺序

1. 确认现有平台、项目、后端及域名管理，沿用可用承载而不是另建一个无法工作的静态演示站。记录当前线上发布编号和恢复办法。
2. 将当前工作区的源文件、测试、锁文件、必要公开 CA 纳入发布清单，排除本地 env、日志、临时诊断脚本、浏览器附件、旧 ZIP 与用户验收数据。用清单和哈希识别版本，不用旧 HEAD 代替。
3. 运行 quality、api:build、build。CI 的付费模型 E2E 不自动触发。5 个跳过用例如实列出，不等于真实数据库测试已过。
4. 在部署平台配置服务端密钥及数据库 TLS、CA、协商方式和必要 DoH。不要复制本机明文历史恢复项；生产宿主的 IPv6、TLS 与网络必须单独验证。历史计划提示曾有凭证暴露，发布前需确认使用的是已轮换的凭证。
5. 先部署受控试用/预览版本；接通 `/api/*`、会话 cookie、登录恢复、账号/过滤器隔离和自选来源。前后端必须属于同一发布清单。没有授权的新增付费资源不自行购买。
6. 以健康检查、浏览器、来源检查和登录态读确认部署；真实研究的付费预算单独确认。成功条件不只是 HTTP 200，而是状态、阶段、证据、保存与当前页面一致。
7. 试用地址和限制说明确认后交给测试者；保留原线上版本，若核心路径失败即恢复原版。尚未完成第 1 步，不能声明已上线。

## 3. 小规模用户测试方案

建议先招募 **3–5 人，7 天**，作为受控试用设计，不是系统容量承诺。优先 2 位已有 AI 工具使用经验的人、1 位创作工作者、1 位普通非技术使用者；教育行业用户可以测试明确来源与问题，不能由此宣称政策覆盖。邀请由用户发出，本轮不向外发送消息。

每位用户先完成这些任务：

| 任务 | 观察什么 | 判定证据 |
|---|---|---|
| 提出一个自己确实关心的问题 | 是否能理解问题和筛选配置 | 原问题、操作耗时、卡在哪里 |
| 阅读一条结果并打开原文 | 答案是否相关、依据是否支持主张 | 用户能指出事实与未知；来源能打开 |
| 添加一个公开原文链接 | 检查、保存、刷新是否可理解 | 检查状态和原因，重开保留情况 |
| 做一次已知/没用/改变看法反馈 | 语义、保存提示和账号持久性 | 实际按钮、响应、重开读回 |
| 在后续有预算的研究中复用记忆 | 是否正确处理已知与新证据 | 下一次真实 requestId 与对应去向 |
| 遇到空结果或失败 | 是否能区别无更新、证据不足、请求失败 | 用户用自己的话解释状态；不要求强行有卡片 |

不要要求每人连续触发大量研究。试用开始前应约定总付费预算、单人频次和停止条件；一次提交可能包含多次模型调用。当前尚未测得生产并发容量，Supabase 免费套餐也不能据本地 1/3/5 并发只读基线换算为用户人数。

## 4. 记录和衡量

反馈表：匿名测试编号、时间、线上版本、原问题（用户同意后记录）、requestId、期望、实际结果、阶段、原文 URL、反馈动作、是否读回、截图是否脱敏、费用可观测情况、任务是否完成。

同时统计两类结果：
- **工程**：业务完成率、失败阶段、响应时长中位数/P95、账号保存和隔离、来源读取失败率、可观测调用成本。小样本 P95 只作观察，标样本量。
- **价值**：用户是否获得此前不知道且与问题相关的信息、能否核对依据、有没有节省查找时间、是否愿意下次主动使用。

Adobe 当前“资料库保留但今日零条”必须向测试者如实说明；不能把安全拒绝或规则正确执行当成用户任务成功。没有模型逐次日志时不声称精确成本或调用数。

## 5. 停止和回滚条件

出现跨账号数据、凭证泄漏、错误标注事实、持续保存失败或旧结果冒充本次时，停止扩大试用，保留证据并回滚；单个来源无法读取先分类，不无界重试。不得为使任务通过放宽 SSRF/TLS/证据门槛。

本阶段结束时交付：线上发行与回滚记录、匿名化试用任务表、前三个高影响问题及取舍、实际通过与未通过场景。没有足够证据就延长试用，不追加行业、自动推送或自主学习宣传。
