# 网页与平台信源采集

优先使用现有公开 RSS/Atom、官方 changelog 和支持的公开 API。没有订阅入口时，用当前环境可用的搜索或浏览器工具读取实际页面；只从可见内容提取材料，不猜测接口、文章或发布日期。

## 采集与接入

1. 读取当前问题的实体、任务、排除项、地区和时间窗。优先找官方发布页，媒体用于补充，平台帖子用于发现线索。
2. 从官网的订阅链接或文档确认 feed/API 地址。分别记录 HTTP 成功、解析成功、候选产生和最终筛选通过；HTTP 200 的 HTML 登录页不是 RSS 成功。
3. 对每条材料保留 `title`、`sourceUrl`、`publisher`、`sourceType`、`publishedAt`、`retrievedAt`、`evidenceSnippet`、`verificationStatus`。缺失发布日期留空；抓取时间不能代替发布时间。
4. 社交帖子标记为未验证线索，查找一手材料确认。没有独立证据时不得写成事实或自动确认知识。
5. 用标准 URL 和事件主题去重，保留原始证据。返回结果说明关联问题的哪一部分；旧材料、导航页、广告、仅标题信息分别标明限制。
6. 若要进入线上筛选池，使用现有 `source-registry/feed-catalog.ts` 与 `research/registered-feeds.ts`（或既有自定义来源路径），补来源选择和候选链路测试。创建本 skill 不会自动完成线上接入。

## 访问边界与失败处理

- 不绕过验证码、登录墙、付费墙或访问限制，不复制浏览器 Cookie/令牌到产品或日志。需要平台身份时使用已授权会话或正式 API，未配置标为未配置。
- 产品抓取继续使用现有安全读取器，保留公网地址校验、跳转校验、响应大小与截止时间限制。诊断用本机 fetch 的成功不等于安全读取器或腾讯云成功。
- 来源失败、空列表、未搜索、预算停止分别记录，不合并成“没有消息”。单一环境故障只确认一次，不循环尝试；其余可用来源继续。
- 不点赞、评论、关注、发帖或发送消息。新增付费 API、依赖或平台权限需单独明确范围。

交付时分开说明：发现的来源、已解析条目、进入产品候选的条目、实际通过筛选的条目，以及本地/云端证据。可复用已有 social-signal-research 的证据规则，无需重复采集同一材料。
